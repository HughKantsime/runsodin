ODIN release pipeline

Manual, evidence-bound, build-once, and rollback-preserving.

1. Validate and authorize

  1. Bump and commit the version.
  2. Create the exact release-candidate/<SHA> ref.
  3. Run Trusted Validation; all ten components must pass.
  4. Run Promotion Eligibility for stage.

2. Publish immutable image

The publication workflow builds once to a run-unique staging tag, starts and checks the exact amd64 and arm64 manifests by digest, then attaches sha-<SHA> and vX.Y.Z. Conflicting immutable tags fail closed. It never writes latest.

3. Promote production

A fresh production eligibility decision, protected-environment approval, valid public TLS, healthy current production, and the exact publication receipt are mandatory. The workflow preserves prior latest as rollback-<run>-1, then copies the already-tested OCI digest to latest without rebuilding.

Rollback

The production receipt is authoritative. Use its prior digest and registry-native restoration command to move latest back, verify the registry digest, and observe public health after Watchtower reconciles. Direct-host semver pinning is break-glass only.

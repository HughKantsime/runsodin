# ODIN EDU Privacy Data Map

Status: engineering inventory, not legal advice or a signed data-processing agreement.

| Data | Purpose | Primary storage | Access | Export / erasure | Retention / backup notes |
|---|---|---|---|---|---|
| Username, email, role, group and organization membership | Authentication, authorization, approvals and attribution | `users`, organization/group tables; HttpOnly session cookie | User; authorized administrators | User export; erasure anonymizes identity and revokes sessions/tokens | School must select retention and contract-end deletion policy; SQLite backups retain historical copies until backup expiry |
| Session metadata, API-token hashes and short-lived WebSocket tokens | Account security and session management | session/token tables; WebSocket tokens exist only in memory and connection URLs for their five-minute lifetime | Account owner; authorized administrators | Included in account lifecycle; erased/revoked with account | Never store raw tokens in browser storage or logs; WebSockets reject anonymous and normal access tokens |
| Job name, file metadata, submitter, approval outcome and printer assignment | Print workflow | job, print-file, model and audit tables; upload volume | Scoped users and authorized staff | User export where attributable; identifiers anonymized on erasure | Uploaded content may itself contain personal data; school policy must restrict filenames/content |
| Printer identifier, address, credentials and telemetry | Printer connection and fleet operation | printer/config tables; encrypted credential fields; telemetry tables | Authorized operators/admins | Not student export unless attributable | Credentials excluded from reports, logs, readiness artifacts and backups shared outside the operator boundary |
| Quotas, usage, report/CSV rows and chargebacks | Classroom limits and operational reporting | quota/job/report queries and generated downloads | Scoped user; authorized staff | User export and erasure canary-tested | Downloads leave ODIN's control; school must govern destination, sharing and deletion |
| Audit events | Security, approvals and accountability | audit tables | Authorized administrators | Historical actor identity is anonymized according to erasure implementation | Define institutional audit-retention period; new erasure audit contains only anonymized subject ID and actor ID |
| Logs, alerts and diagnostics | Reliability and incident response | application logs, alert tables, support bundle | Operators/admins | Privacy-filtered support bundle | Logs must not contain auth tokens, credentials, student exports or former erased identifiers |
| Backups | Recovery | configured backup directory, mode `0600` | Authorized administrators and host operators | Not directly user-downloadable | Backups are encrypted only when the host/storage layer provides it; define expiry, off-site protection, restore testing, RPO and RTO |
| Browser preferences | Theme, density, layout, locale and tour state | `localStorage` | Browser user | Cleared independently by browser controls | Identity, roles, permissions, tokens, reports and student/job data are forbidden from persistent browser stores |
| Real-time UI events | Printer/job state and user alerts | In-memory authenticated WebSocket connections; short-lived event queue | Explicit recipient, matching organization, shared-printer users, or all authenticated users for genuinely global state | Connections end on browser/session lifecycle; event queue expires | Delivery is user/organization scoped where the event references a recipient or printer, and readiness load tests assert zero cross-user targeted events |

All API and OpenAPI responses carry `Cache-Control: no-store` and `Pragma: no-cache` so shared lab browsers and intermediary caches do not retain student/user/job/report/auth state. EDU deployments must configure exact `TRUSTED_HOSTS` and `CORS_ORIGINS`; the general self-hosting wildcard Host default is not an EDU production setting.

Integrations and subprocessors are deployment-specific. At minimum, inventory SMTP, OIDC identity provider, browser push service, printer/vendor cloud connections, object/backup storage, hosting, monitoring, and support systems before contracting with a school.

Product controls do not replace school obligations. The institution and vendor must settle FERPA school-official terms where applicable, COPPA authority for under-13 use, California student-data contract clauses, breach notification, record review/correction, retention, contract-end deletion certification, accessibility procurement, and incident contacts.
